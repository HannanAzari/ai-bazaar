## What every candidate must leave behind

Per the [World Bible](NESTUDIO_WORLD_BIBLE.md) rule *"No learning may disappear,"* each candidate records:

- **Why it survived** — the emotion it advanced, the test(s) it passed.
- **Why it died** — the specific weakness, in emotional terms.
- **Which rule it violated** — the World-Bible / DNA law it broke (if any).
- **Which emotion improved** — what got stronger versus its parent generation.

These live in `manifest.json` (`candidate.history`) and, for archived candidates, in a frozen
`record.json` beside the image. This document summarizes the *narrative* — the story of how the icon was
found — so a future designer can read the journey, not just the data.

## Log format (per session)

```
### <date> · Round <n> · <experiment id> — <hypothesis>
- Generated: 5 (engine, prompt icon@N)
- Survived: <candidate id> — <why: emotion advanced / tests passed>
- Died: <ids> — <why, in emotional terms> [rule violated]
- Emotion improved: <what got stronger>
- Decision: advance / improve / cut
- Next action: <what to try next>
- CLOSING QUESTION — "Did we create something people will remember, or just something that looks nice?"
  → <honest answer, and what it implies for the next session>
```

## The closing-question ledger

Every session ends by answering, honestly, **"Did we create something people will remember, or just
something that looks nice?"** The running answer to that question — session over session — *is* the true
measure of the project. A string of "just nice" means the search has stalled and the hypothesis must change;
a "yes, remember" marks a real step toward the icon. This ledger is the heartbeat of Nestudio's design.
